# MNCS pressure log

Consumer-driven language-development evidence for the ScratchTrack
conversion campaign. Each item follows the required shape:

**ScratchTrack requirement → MNCS limitation → upstream solution → proof**

## Baseline (2026-09-06, pre-conversion)

- ScratchTrack tests: 50 passed (6 files).
- Production bundle: `dist/assets/index-D9MHhpMm.js` 284,131 bytes,
  `index-6a74pugY.css` 35,955 bytes.
- MNCS meter WASM module (`scratchtrack.meter.v1`, 11 functions): 2,983
  bytes, zero host imports.

## Delivered

### D-001 — exact integer meter kernels in MNCS (Phases 1+2)

- Requirement: meter, tick, subdivision, step, and pad-note math must be
  exact (24-tick grid; triplets land exactly).
- MNCS limitation: none for this slice — Profile 0.6 scalars, boolean
  operators, and explicit arithmetic intents already express it.
- Solution: new `mncs/meter.mncs` (`scratchtrack.meter.v1`), kept in
  ScratchTrack because music theory is product-domain, not stdlib-generic.
  Float `barBeats`/`STEP_BEATS` reasoning replaced by `bar_ticks =
  numerator * 96 / denominator` and divisibility-checked `steps_per_bar`.
  Addition/multiplication use explicit wrapping intents (`+%`, `*%`),
  discharging 13 of 29 overflow obligations; the wrap path is unreachable
  in product ranges (numerators <= 32, MIDI 0..127, ticks <= 1536).
- Proof: `mncs/meter-corpus.json` (33 cases) executes 33/33 on
  portable-WASM and research-bytecode; compiled WASM instantiates with zero
  imports and 12/12 live calls agree; `src/mncsMeter.test.ts` pins every
  vector in the app suite; `scripts/mncs-evidence.sh` replays it all.
  Semantic fingerprint `17dbdf26...` (see script output).
- Ratio effect: `music.ts` `barTicks`/`stepsPerBar`/`STEP_TICKS` now
  delegate to the MNCS projection; all 50 pre-existing tests still pass
  unchanged (plus 7 new conformance tests).

### D-002 — arrangement/state kernels in MNCS (Phase 3)

- Requirement: transport scheduling math, clip activation/length, session
  caps, and tempo policy must be exact and total.
- MNCS limitation: almost none for the tick-space slice — but two real
  ones surfaced: `let` bindings are single-assignment (clamp shapes use
  Profile 0.8 scalar `select` instead), and `next` is a reserved word
  (bindings renamed). Record values cross backends only in canonical
  name-sorted field order with exact `type_identity` — discovered by a
  failed probe, now pinned in `scripts/mncs-arrange-corpus.py`.
- Solution: new `mncs/arrange.mncs` (`scratchtrack.arrange.v1`, Profile
  0.8) with `Clip`/`Loop` records: session policy (12 takes, 36
  Scratches), `normalize_bpm`, sanitize/end/activate/length/move/resize/
  snip kernels, `wrap_tick`, `step_index`, motif clamp/sizing, loop
  normalization. Transport `fireTick`, all take/scratch guards, and
  `project.ts` tempo delegate to `src/mncsArrange.ts`; beats→ticks
  rounding stays at the edge.
- Proof: `mncs/arrange-corpus.json` (53 cases, generated by
  `scripts/mncs-arrange-corpus.py`) executes 53/53 with expectations met
  on both backends; compiled WASM (2,702 bytes, zero imports) verified
  with 19/19 live scalar calls; `src/mncsArrange.test.ts` pins every
  vector including a JS-formula cross-check for wraps. Semantic
  fingerprint `015a0d47...`. Replay: `scripts/mncs-evidence.sh`.
- Ratio effect: ~15 call sites in `App.tsx`/`project.ts` now delegate;
  snip/move/resize/loop-range *beats* editing stays host-side per P-007.

### D-003 — migration math in MNCS (Phase 3 continued)

- Requirement: v1/v2/v3 → v4 document migration (legacy meter mapping,
  drum-pattern remap, key normalization, Auto Scratch upgrade rule) must be
  exact and total over untrusted JSON.
- MNCS limitation: none new — bools cross cleanly as `{"boolean": ...}`
  (used for `auto_scratch_upgrade`), and the tie case below needed no
  language change.
- Solution: new `mncs/migrate.mncs` (`scratchtrack.migrate.v1`, Profile
  0.8): `legacy_numerator`, `remap_index`/`remap_cell` (one proven rule
  replacing the duplicated float implementations in `music.ts`
  `remapPattern` and `project.ts` `remapRows`), `content_bars`,
  `normalize_root`/`normalize_octave`, `auto_scratch_upgrade`. Both remap
  copies, the legacy meter mapping, synth key normalization, motif-bar
  clamping, and the Auto Scratch version rule delegate to
  `src/mncsMigrate.ts`.
- Proof: `mncs/migrate-corpus.json` (38 cases, generated by
  `scripts/mncs-migrate-corpus.py`) executes 38/38 with expectations met
  on both backends; compiled WASM (1,260 bytes, zero imports) verified
  with 10/10 live calls; `src/mncsMigrate.test.ts` pins every vector plus
  an exhaustive 2..128 grid cross-check. Semantic fingerprint `a78100b1...`.
- Intentional normalization: exact ties (.5 positions) now round up
  deterministically. Exhaustive measurement over steps 2..128: 160 of
  1048385 combos differ from legacy float, ALL exact ties, ALL previously
  dust-down, now up. This is the campaign's exact-over-dust principle
  applied openly — not silent drift.
- Deferred with reason: `content_bars` is proven but not delegated on the
  migration path (float-beat dust near bar boundaries can flip `ceil`
  after tick rounding — second instance of P-007).

### D-004 — visual/interaction kernels in MNCS (Phase 6+7)

- Requirement: drum geometry classification, swing phase, piano-roll
  pointer interpretation, MIDI policy, grid-line counts, and waveform
  bucket partitioning must be exact over whole units.
- MNCS limitation: MNCS `/` truncates, but visual grids need floor for
  negative offsets — answered with a reusable `floor_div` primitive
  (pressure-noted, kept product-local until stdlib wants it). Trig (drum
  orbit, cos/sin) and float peaks stay host-side: no float/trig vocabulary
  exists (P-001, new P-008).
- Solution: new `mncs/geometry.mncs` (`scratchtrack.geometry.v1`, Profile
  0.8) with a `Bounds` record: `is_beat_step`, `swing_applies` (one rule
  replacing the App/DrumEditor copies), `steps_per_beat`, `cycle_cell`,
  `advance_step`, `floor_div`, `row_delta`, `drag_started`,
  `tap_cancelled`, `clamp/shift_motif_midi`, `pick_row_midi`,
  `half_beatline_count`, `bucket_bounds`/`bucket_stride`. DrumEditor,
  DrumGeometry, MotifEditor, WaveformDisplay, and App swing sites delegate
  to `src/mncsGeometry.ts`.
- Proof: `mncs/geometry-corpus.json` (52 cases, generated by
  `scripts/mncs-geometry-corpus.py`) executes 52/52 with expectations met
  on both backends; compiled WASM (2,647 bytes, zero imports) verified
  with 16/16 live calls in `scripts/mncs-evidence.sh`; tests pin every
  vector plus a -260..260 `Math.round` cross-check for row deltas.
  Semantic fingerprint `edd7c6a6...`.
- Representation note: the cross-check caught `Math.round(-0.5) === -0`
  vs MNCS integer `0` — same value, no product effect; the sweep compares
  with `===` semantics and documents it.

### D-005 — WAV/PCM container kernels in MNCS (Phase 4+8)

- Requirement: WAV encode/decode header math, container validity, and
  leading-magic media classification must be exact over byte offsets.
- MNCS limitation: two sharp edges surfaced, both answered without
  language changes. (1) Explicit-intent operators reject mixed-type
  operands *positionally*: `36 +% data_size` (literal-first) fails while
  `samples *% 2` (value-first) elaborates — `(36 as u32)` casts work.
  Upstream should either accept literals on both sides or fail on both.
  (2) Sequence-typed functions (`[byte; 44]`, `[byte; 12]`) prove fully
  through experiment observations, but live host calls need arena-cell
  pointers (`mncs_host_buffer`) — scalar size laws additionally verify
  with direct live calls.
- Solution: new `mncs/wav.mncs` (`scratchtrack.wav.v1`, Profile 0.7 —
  the first slice on the bounded-data substrate): explicit little-endian
  decoders, canonical field offsets, magic/validity policy, size laws,
  and the 1..4 magic-code table. `media.ts` magic classification, header
  reads, validity gates, and encode size computations delegate to
  `src/mncsWav.ts`. Byte access and float sample scaling stay host-side
  at the boundary.
- Proof: `mncs/wav-corpus.json` (28 cases over real built headers,
  generated by `scripts/mncs-wav-corpus.py`) executes 28/28 with
  expectations met on both backends; compiled WASM (3,251 bytes, zero
  imports) verified with 6/6 live scalar calls; tests pin every vector
  plus an app encoder round-trip. Semantic fingerprint `87becf6d...`.
- Deferred with reason: per-sample PCM scaling and float peaks need the
  float tranche (P-001); variable-length container parsing (fragments,
  longer headers) needs offset-chasing dynamic iteration (P-012 shapes)
  beyond whole-view traversal.

### D-006 — ZIP-store layout kernels in MNCS (Phase 8)

- Requirement: project-pack read/write layout (local headers, central
  directory, EOCD) must be exact over fixed field offsets.
- MNCS limitation: the CRC32 core is NOT expressible — probed and
  refused: `u32 ^ u32` and `u32 >> u64` fail the type checker (shifts/XOR
  exist for `byte` only), the 256-entry table exceeds the 64-element
  sequence bound, and table-free bitwise update needs counted loops.
  New P-009 files this (u32 bitwise ops + bulk/counted iteration); the
  pack.ts CRC32 table stays host-side with reason.
- Solution: new `mncs/pack.mncs` (`scratchtrack.pack.v1`, Profile 0.7)
  with an `Entry` record: fixed-window LE readers, signatures, per-entry
  parse, walk arithmetic, and write-path sizes. `pack.ts` record sizes,
  signature checks, entry parsing, and walk steps delegate to
  `src/mncsPack.ts`; the EOCD backward scan, per-entry loops, CRC32, and
  text coding stay host-side.
- Proof: `mncs/pack-corpus.json` (24 hand-built windows, generated by
  `scripts/mncs-pack-corpus.py`) executes 24/24 with expectations met on
  both backends; compiled WASM (2,667 bytes, zero imports) verified with
  5/5 live scalar calls; tests pin every vector plus an app pack
  round-trip. Semantic fingerprint `c67e9fbb...`.
- Module-shape note: scratchtrack modules stay self-contained (LE readers
  duplicated across wav/pack). The file resolver maps dotted module
  names onto directory paths, but its last candidate is a sibling named
  after the final segment — so `use scratchtrack.le;` WOULD resolve to
  a flat `mncs/le.mncs`. The dedup still fails for a deeper reason:
  exact sequences do not coerce to bounded views (`[byte; 44]` vs
  `[byte; up_to 64]` is MNE133), so one reader cannot serve the
  44/46/22-byte windows. New P-010 files this.

### D-007 — position-text parsing in MNCS (text slice)

- Requirement: `bar.beat.sixteenth` position strings must parse exactly
  (digit scanning, part structure, defaults, validity) with tick
  computation in whole ticks.
- MNCS limitation: none for the parse direction — Profile 0.7
  `iterate i over view carrying state` folds bytes through a `PState`
  record; formatting stays host-side (no text value type, P-002).
- Solution: new `mncs/text.mncs` (`scratchtrack.text.v1`, Profile 0.8):
  `is_digit`, `parse_step`, `parse_position` (whole-view fold with
  missing-part defaults beat 1 / sixteenth 0), `position_ticks` (range
  policy with TOTAL_BEATS cap). Two intentional normalizations:
  surrounding whitespace and `Number()` spellings (`0x10`, `1e3`) are
  rejected, and digit runs past u64 wrap (total, documented).
- Proof: `mncs/text-corpus.json` (23 cases, generated by
  `scripts/mncs-text-corpus.py`) executes 23/23 with expectations met
  on both backends, zero cross-backend mismatches; compiled WASM
  (2,878 bytes, zero imports) verified with 5/5 live sequence-ABI
  calls plus `is_digit`/`position_ticks`; `src/mncsText.test.ts` pins
  every vector; replay: `scripts/mncs-evidence.sh`. Semantic
  fingerprint `0322e478...`.
- Production: `parsePosition` in `music.ts` runs compiled
  `parse_position`/`position_ticks` WASM-first with projection
  fallback (the first sequence-taking MNCS function on the browser
  path — see D-009).

### D-008 — IEEE 802.3 CRC32 in MNCS (crc slice)

- Requirement: project-pack integrity checksums must be exact (the
  flagship P-009 workload; `pack.ts` carried a hand-rolled table).
- MNCS limitation: integer `^`/`&`/`|` are refused for every integer
  type (only `byte` has them; `u64 >>` and `%` exist), the 256-entry
  table exceeds the 64-element sequence bound, and nested bounded
  iteration is refused (MNE147). All three probed before designing.
- Solution: new `mncs/crc.mncs` (`scratchtrack.crc.v1`, Profile 0.7)
  routing around every edge: full 32-bit XOR via per-bit add-mod-2 in
  a literal-counted loop (the counted index is not bound in the body,
  so shifting copies thread through the carried record); a 16-entry
  reflected nibble table indexed dynamically (OOB traps cleanly);
  two 4-bit stages per byte instead of nested loops; streaming across
  windows via host-threaded state (`crc_init`/`crc_update`/
  `crc_finalize`, chunk-associative by construction).
- Proof: `mncs/crc-corpus.json` (15 cases, generated by
  `scripts/mncs-crc-corpus.py` with zlib as independent oracle,
  including two-chunk streaming with pinned intermediate states)
  executes 15/15 with expectations met on both backends, zero
  mismatches (worst case 913,526 steps, inside budget); compiled WASM
  (2,547 bytes, zero imports) verified single-window and 4-byte-chunk
  streamed (both 0xCBF43926); `src/mncsCrc.test.ts` pins vectors;
  `pack.ts` delegates its checksum to `mncsCrc32` (WASM-chunked first,
  table fallback). Replay: `scripts/mncs-evidence.sh`. Semantic
  fingerprint `23a7cf91...`.
- Cost honesty: per-bit arithmetic runs ~14k steps/byte (~200
  steps/loop-iteration). Native integer XOR (P-009) would collapse
  this by roughly two orders of magnitude — the module proves
  expressibility, not efficiency.

### D-009 — production WASM execution path (loader + host ABI)

- Requirement: P-006's end state — real browser WASM instead of TS
  mirrors, for scalar AND sequence-taking functions.
- Solution: `src/mncsWasm.ts` loads `meter.wasm` + `text.wasm` +
  `crc.wasm` at boot (never throws; per-module readiness flags;
  projections are the fallback, never a second authority). Byte views
  cross through the documented host-buffer ABI (`mncs_host_buffer` +
  packed `offset | len << 32` descriptors; records return as pointers
  to 8-byte-slot canonical cells) — reverse-mapped from
  `mncs-codegen` (`lower.rs`/`wasm.rs`) and verified call-by-call
  against the real artifacts. `barTicks` and `parsePosition`
  (`music.ts`) plus pack checksums (`pack.ts` via `mncsCrc32`) execute
  WASM-first in production.
- Proof: `src/mncsWasm.test.ts` live-calls all three checked-in
  artifacts (scalar, sequence-ABI, and chunked-streaming paths);
  `scripts/mncs-wasm-build.sh` rebuilds all 8 artifacts
  byte-deterministically with a source-bound manifest that
  `scripts/verify-mncs.sh` re-checks; `.github/workflows/mncs-verify.yml`
  runs the whole boundary on every PR/push to main via
  `mncs-actions/actions/verify` (pinned SHA) plus badge rendering.
- Fabric cross-check: `fabric/text-boundary-audit/` declares the
  checked-in boundary as a `mncs-fabric` job (plan validate → run
  local → record verify, all PASS; see `docs/fabric-log.md`).

## Open pressure (upstream work, ordered by campaign value)

### P-001 — float semantics (blocks Phase 4 audio/DSP)

- Requirement: envelopes, gains, pan curves, compression config, MIDI
  frequency, waveform analysis are float workloads.
- MNCS limitation: integer-only today (`i8..i64`, `u*`, `byte`, `bool`);
  no float type, no float intents, no backend float envelope.
- Upstream path: float scalar type + explicit intent family (analogous to
  `+%`/`+|`), backend realization facts, bounded float corpora. DSP stays
  host-side until this lands; `audio.ts` parameter math is the waiting
  workload.

### P-002 — string/UTF-8 vocabulary (blocks Phases 7+8)

- Requirement: note names, scale labels, JSON keys, Drive metadata,
  position strings (`bar.beat.sixteenth`) are string workloads.
- MNCS limitation: no string type; `byte` + bounded views + `text_view`
  cover spans and matching but not general string values.
- Status this run: the PARSE direction now crosses — `parse_position`
  takes UTF-8 bytes staged through the host-buffer ABI and the browser
  runs it (D-007/D-009). Text PRODUCTION (`formatPosition`, note names,
  labels) stays host-side.
- Upstream path: bounded string/value-text tranche above `text_view.v1`;
  until then, enumerations cross the WASM boundary as integer codes
  (`SUBDIVISION_CODES` in `src/mncsMeter.ts`).

### P-003 — guarded-division obligations stay UNKNOWN

- Requirement: `steps_per_bar`, `quantize_tick`, `pitch_class` guard every
  divisor by control flow (`step <= 0` early-return; validated
  denominators; literal 12).
- MNCS limitation: no prover discharges divisor-nonzero facts, so 16
  `integer-overflow` obligations remain UNKNOWN and top-level experiment
  status is UNKNOWN (bounded observations still carry verified values —
  same contract as the `bounded-min` precedent).
- Upstream path: range/provenance reasoning that turns guarded divisors
  into discharged obligations. ScratchTrack's kernels are a ready-made
  corpus for it.

### P-004 — async/effect model (blocks Phases 8+9)

- Requirement: microphone capture, IndexedDB, Drive sync, file picker are
  async capability workloads needing an explicit host-access model
  (`audio.capture`, `storage.read`, ...).
- MNCS limitation: `capability/` in the stdlib is explicitly reserved and
  empty; no async/effect/callback/future semantics exist yet.
- Upstream path: capability/effect-shape declarations per current RFC
  direction; ScratchTrack's `store.ts`/`drive.ts`/`capture.ts` are the
  waiting workloads. Nothing async was wrapped in promises-shaped TS glue
  this tranche.

### P-005 — packed render data / typed buffer views (blocks Phase 6)

- Requirement: waveform/drum/timeline geometry wants packed numeric
  buffers shared with the host (zero-copy or minimum-copy).
- MNCS limitation: bounded sequences/views exist; the host-buffer ABI
  (`mncs_host_buffer` + packed descriptors) is now PROVEN from a JS
  host for byte views in both directions (D-009: parse in, record
  pointer out) — but only by reading compiler internals, and only for
  bytes. The browser `Float32Array`-over-memory path is unproven.
- Upstream path: published host-view/record ABI contract (see new
  P-011) + browser interop test. Geometry stays host-mapped until then.

### P-007 — arrangement snap grids are finer than the transport grid

- Requirement: clip move/resize/snip and loop-range editing work in beats
  with snap grids down to 1/32 beat (0.75 ticks) plus free drag.
- MNCS pressure finding: those edits are not whole-tick-exact, so they
  cannot delegate to tick kernels without changing stored values. The
  tick kernels are specified, proven, and tested and waiting.
- Upstream/product path: either make snap grids tick-exact (product
  decision: drop or reinterpret sub-tick grids) or bless an explicit
  round-at-edit rule, then move beats editing into MNCS. Until then the
  beats→ticks `Math.round` stays at the transport edge by design.

### P-009 — integer bitwise ops and the 64-element sequence bound

- Requirement: checksums/hashes and multi-byte wire math want native
  XOR/AND/OR/shifts over 32-bit (and wider) integers plus tables
  bigger than 64 entries.
- MNCS limitation, narrowed by probes this run: `^`/`&`/`|` are
  refused for EVERY integer type (`crc_u64_attempt.mncs`:
  MNE115/117/119; only `byte` has them) while `u64 >>` and `%`
  exist — the gap is exactly integer bitwise combinators, not
  shifts. Fixed sequences cap at 64 elements (`mncs_model::
  MAX_SEQUENCE_BOUND = 64`), so the 256-entry CRC table cannot exist.
- PROVEN this run (former sub-claims, now closed): literal-counted
  loops (`iterate step up_to N`), whole-view traversal with carried
  state, dynamic `xs[start..end]` slicing, dynamic indexing into
  exact sequences (trap-on-OOB), and `u64` shifts all elaborate and
  execute — `mncs/crc.mncs` (D-008) is the existence proof that routes
  around every remaining edge at ~14k steps/byte.
- Upstream path: native integer bitwise tranche (collapses CRC32 cost
  by ~100x and unlocks WAV RIFF field assembly); consider raising or
  paging the sequence bound for lookup tables.

### P-008 — trig and float geometry stay host-side

- Requirement: drum-orbit positioning (cos/sin), waveform peak
  accumulation, pixel layout, and colors are float/trig workloads.
- MNCS limitation: no float type and no trig vocabulary (extends P-001).
- Status: the discrete skeleton around those workloads (classification,
  thresholds, partitioning, counts) is now MNCS-owned (D-004); the
  continuous parts wait on the float tranche, which should include a trig
  decision (intrinsics vs host callbacks).

### P-010 — exact sequences do not coerce to bounded views

- Requirement: one shared little-endian reader module (`mncs/le.mncs`)
  for the 44-byte WAV, 46-byte local/central, and 22-byte EOCD windows.
- MNCS limitation (probed, refused): `[byte; 44]` does not satisfy a
  `[byte; up_to 64]` parameter (MNE133, `subtype_attempt.mncs`). The
  import itself would resolve — the file resolver's last candidate is
  a sibling named after the final segment, so `use scratchtrack.le;`
  finds a flat `mncs/le.mncs` — but no generic reader can accept the
  differently-sized windows, so LE readers stay duplicated per width.
- Upstream path: exact→bounded-view subtyping (or sequence generics).
  Unlocks `mncs/le.mncs` and removes six duplicated readers.

### P-011 — host view/record ABI is codegen-internal, not a contract

- Requirement: every JS host that calls sequence-taking MNCS functions
  re-derives the marshalling from compiler source (`mncs-codegen`
  `lower.rs`/`wasm.rs`): packed view descriptors, 8-byte-slot
  canonical cells, the allocator/host-buffer/reset protocol, the
  internal bit-0 marker on derived byte views.
- MNCS limitation: no versioned, published host-ABI document; the
  target-contract facts (`experiment run` output) describe backend
  properties, not a callable host contract. A codegen change can
  silently break every host driver (D-009's loader included).
- Upstream path: publish the host ABI as a versioned contract with a
  conformance vector (stage bytes → call → read record) per composite
  shape. Unlocks third-party hosts and hardens the browser path.

### P-012 — nested iteration refused; counted index unbound

- Requirement: two-level loops (bit-steps within byte-steps, the
  natural CRC32 shape) and position-aware counted loops.
- MNCS limitation (both probed): nested bounded iteration is refused
  outright (MNE147, "Source Profile 0.4 does not permit nested bounded
  iterations"); the counted-loop index is not bound in the body
  (`step` → MNE102), so even single-level counted loops cannot see
  their position — state must thread shifting copies through the
  carried record (the `bitwise_u64_attempt` v1→v2 rewrite documents
  the pattern).
- Upstream path: allow nested bounded iteration within the step
  budget, and/or bind the counted index (with its declared type in
  the spec). Unlocks the natural 8×N CRC shape and any
  position-dependent counted work. Worked around in D-008, not
  blocking — but every future nested algorithm pays the flattening
  tax until this lands.

### P-013 — WASM view-return divergence (sequence-returning functions)

- Requirement: text production and any kernel that RETURNS a
  sequence (`formatPosition` bytes, labels, keys).
- MNCS limitation (measured, `textprod_slice_attempt.mncs`,
  `textprod_slice-corpus.json`, `experiment run` status FAIL):
  the portable-wasm backend returns the first byte correctly and
  zeroes the rest — case `s02` expected `[48, 55]` (`'0','7'`)
  got `[48, 0]`; case `s13` expected `[55, 46]` (`'7','.'`)
  got `[55, 0]`. Scalar/boolean/record returns are exact
  (events, dsp, doc_keys corpora); only sequence returns diverge,
  consistent with an incompletely-marshalled view descriptor on
  the return path (P-011's unpublished ABI).
- Upstream path: fix the sequence-return marshalling in the
  portable-wasm backend (or publish the return-side view contract
  per P-011 so hosts can detect it). Until then, sequence
  production stays host-side and text production waits on this
  PLUS the P-002 text tranche.
- ScratchTrack code unlocked when fixed: `formatPosition` and
  every byte-producing kernel move into MNCS.

### P-014 — cross-module nominal types unusable

- Requirement: shared event/state vocabularies (one `Transport`
  machine, one `Phase` enum, shared records) across modules.
- MNCS limitation (probed, refused at elaboration,
  `events_import_attempt.mncs`, re-verified this run):
  `MNE105` ×2 (imported type name not in the profile type list)
  + `MNE161` ×1 (field projection needs a declared record type);
  `Os::linux`-style double-colon value paths do not parse
  (MNP066 cascade). `use` resolves and imported FUNCTIONS over
  primitive args work (`doc_keys.mncs` + stdlib
  `json_projection.count_key`, 23/23 on WASM) — only nominal
  TYPES fail to cross.
- Workaround in use: every module re-declares its enums/records
  locally (`events_transport_attempt.mncs` proves the machine
  itself runs 6/6 PASS on WASM with local declarations).
- Upstream path: admit imported finite/record identities in
  signatures, projection, and match scrutinees (with the
  short-form identity spelling the backend already uses — see
  this run's ABI findings). Unlocks shared vocabularies and any
  shared-record architecture.

## Closed gaps (feared blocked, proven supported this run)

- Whole-view traversal with carried record state (`text.mncs` fold).
- Literal-counted loops (`iterate step up_to 32`).
- Dynamic `xs[start..end]` slicing with computed bounds
  (`slice_dynamic_attempt.mncs`, 2/2 on WASM).
- Dynamic indexing into exact sequences, trap-on-OOB
  (`dynidx_attempt.mncs`, 2/2 + clean `runtime_failure`).
- `u64` shifts and `%`/`/` bit extraction.
- Stdlib `json_projection.count_key` end-to-end on WASM
  (`doc_keys.mncs`, 23/23 returned). Needs `MNCS_LIBRARY_PATH`
  exported — without it the import fails MNE173, which is a

## 1. Native integer bitwise operators (`^`, `&`, `|`, shifts for all int types)

  field assembly ports directly.
- **Other ecosystem benefits →** every checksum/hash/cipher workload
  in any MNCS consumer becomes expressible; removes the largest
  known expressibility cliff (everything else in this campaign
  routed around its hole — this one cannot be routed around
  efficiently).

- **Change →** versioned host-ABI document + conformance vectors
